任务：T-003（归属 `src/atlas/cognition/`，T-003 定边界与适配器，T-105 将来在其上做分类）。
按 SPEC §2.14 的已冻结裁决实现，未重新论证其中的任何一条。

## 关键决策

1. **`@earendil-works/pi-ai` 作为 Node 边车，注册零工具**（§2.14 决策一）。
   隔离因此**由构造满足**：模型即便被注入文本说服也没有可调用的东西，
   所以不需要容器/微VM。§4.7 的门槛不是被绕过，是前提不再成立。
2. **`CognitionPort` 是稳定接口，边车只是它的一个适配器**（§2.14 决策二）。
   换 provider / 换模型 / 换回直连 HTTP 都只换实现类。
3. **provider/model/凭据是配置**：默认走 **DeepSeek 官方端点**
   （`api.deepseek.com` + `DEEPSEEK_API_KEY` + `deepseek-flash`），
   可**纯配置**切到环境内兼容凭据（`ATLAS_OPENAI_API_KEY` + `ATLAS_LLM_BASE_URL`）。
   两条路都实测跑通。
4. **降级 = "未分类"，绝不是猜测**（§2.14 决策四）：降级结果 `claims` 恒为空、
   `output` 恒为 None，且必带原因码；与"响亮失败"有明确分界（见 PROTOCOL.md）。
5. **输出契约冻结**（`extra="forbid"`）：claim 里**没有**坐标字段，
   `char_start` 之类在类型层就构造不出来（§2.2）。

## 隔离是怎么被证明的（不是声称）

- 边车自述 `toolsRegistered == 0`，且**真实请求体**里 `tools` 缺失或为 `[]`；
- `inspect` 暴露**静态 import 清单**（真实能力面，恰好 5 项），
  并有 `builtin_available` 作活对照——证明"没导入 child_process"不是因为它不存在；
- **prompt injection 测试**：把 `rm -rf` / 读 `/etc/passwd` 之类的指令作为待处理外部
  内容喂进去，断言 ① 恶意文本确实进了 transcript，② 哨兵目录清单（路径→sha256）
  前后逐字节相同、注入里的 `rm -rf` 字面目标仍在、未产生新文件，
  ③ 边车期间无新增子进程（有活对照：故意起一个 `sleep 0` 确认计数会变）；
- 边车**环境变量最小化**：默认什么都不继承，只有白名单里的宿主变量会进；
  密钥**从不经过环境变量**（随 job 载荷走 stdin，只活在闭包里）。

## 三种已实测失败的防御（§2.14 决策三）

- 围栏 / 说明文字 / 截断 / 多段输出：确定性扫描器，**只在能拿到"恰好一个完整
  JSON 值"时才接受**；不用"正则抓第一个 `{`"（测试里专门把贪心与非贪心的错误
  行为写出来作对照）；
- 模型下架：HTTP 404 + `has been deprecated` ⇒ 降级为 `model_deprecated`
  （本环境的 `ATLAS_LLM_MODEL` 正好指向一个已下架模型，实测复现）；
- 端点不可达 / 超时：降级为 `unreachable_model` / `timeout`（含边车看门狗）。

## 真实调用证据（硬规则 1）

`tools/t003_real_call.py`（默认 skip 的 `ATLAS_COGNITION_LIVE_TESTS=1` 控制测试版）：
官方端点 `deepseek-flash` 返回 4 条 claim、quote 全部逐字命中原文；
边车内 1.9–8.2 s、端到端 6.7–12.5 s；input 236–428 / output 129–1181，
其中 **reasoning 0–1024**（`reasoning=false` 也照样产生）。成本 provider 不报告
（记录为 `null`，不是 0）。详细数字见 `PROTOCOL.md` §7。

同处记录一条**对 T-105 重要的成本发现**：每次调用的墙钟成本几乎全部是 drvfs
（`/mnt/c`）上逐文件读取 `node_modules`——barrel import 在 `/mnt/c` 上约 6 s，
把边车与 `node_modules` 放到原生 Linux 文件系统后是 **87 ms**。
